AWS Nova AI Interview Architecture

Pencil sketch: minimal persistent storage strategy

Figure 1: AWS Nova Interview Flow (High Level)

Flow: Student audio → Transcribe (STT) → Nova (LLM decides next question) → Polly (TTS) → back to student. Only at interview end: transcript + scores written to PostgreSQL. Optional knowledge base queries from pgvector during reasoning.

Figure 2: Storage Strategy (What Persists, What Doesn't)

Key insight: Live interview state (audio, turn logic, message history) never touches the database. Only the final record (transcript + scores) is persisted. This keeps interviews fast and DB queries lean.

Figure 3: The "Minimal Storage" Contract

Contract: During interview, nothing is persisted except session metadata (once). Turns are logged async (fire-and-forget; loss doesn't break the live interview). Only at end is the scorecard written synchronously. This maximizes latency and reliability.
Why minimal storage?
• Faster database (less I/O during live call)
• Lower latency (no blocking writes mid-turn)
• Simpler recovery (session close is idempotent)
• Smaller attack surface (less PII in transit)
AWS Cost Breakdown (per 20-min interview):
• Transcribe: ~$0.08 (pay per second of audio)
• Nova (Bedrock): ~$0.15 (pay per token)
• Polly: ~$0.15 (pay per character of generated speech)
• Total: ~$0.38/interview (vs. OpenAI Realtime ~$14)
