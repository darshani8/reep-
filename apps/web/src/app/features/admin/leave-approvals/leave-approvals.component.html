Leave policy

  • Signatures · two distinct approvers; you cannot sign twice, and you cannot decide your own request. Each one records the function it was given in — mentor, delegated approver, or the Main Admin.
  • Who sees a request · a mentor sees their own group only; a scoped grant of mentor.leave_approve reaches a department or a college; the Main Admin sees every request, staff leave included.
  • Allowances · recorded per person, per printed option, per academic year, behind Edit. An account with no allowance recorded is not measured against one, which is not a balance of zero.
  • Refusing · this console will not send a refusal without remarks, and the applicant reads them.
info The first three lines are the rule the API enforces; the fourth is this screen's own — POST /leaves/…/decision accepts a refusal with no note, so a refusal made elsewhere can still arrive wordless. There is no stored rule for WHO signs each step: a second signature for staff leave exists only where the office has granted mentor.leave_approve a scope in Governance, and until it has, a staff request can reach its first signature and go no further.
